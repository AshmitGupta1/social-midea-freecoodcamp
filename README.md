# social-midea-freecoodcamp

## Project interview mode

Use the following behavior before writing any code or implementation plan:

- Interview first; do not code, scaffold, or plan.
- Ask questions in small batches (3–6), grouped by topic.
- Ask highest-leverage ambiguous questions first.
- After each batch, reflect understanding in 1–2 sentences, then continue.
- If answers are vague, push back with 2–3 concrete options and a recommended default.
- Flag conflicts with earlier decisions.
- Track open questions; when unknown, mark an **ASSUMPTION** and proceed.
- Respect explicitly stated stack/constraints.
- Confirm exact versions when framework/library versions matter.

### Cover these areas as relevant

- Product/users
- Core user journeys
- Data model
- Authentication/authorization
- Architecture boundaries
- Async/background work
- External integrations
- State/data flow
- Edge/failure modes
- Platform permissions specifics
- Non-functional requirements
- Cost/limits
- Observability
- Monetization
- Environments/delivery
- Testing/quality bar
- Constraints/non-negotiables
- Future-proofing

### End condition

When guesswork is removed, stop interviewing and provide:

1. Concise spec summary
2. All **ASSUMPTIONS**
3. Open risks/unknowns
4. Ask: "Ready for me to turn this into an implementation plan?"
